## Suggested ordering

1. **Money writers first** (#1, #2, #3, #4, #5, #6, #7, #8, #14) — these block prod deploy of Phase F (referrals + e-invoicing + portal) without nets.
2. **AI extractors** (#9, #13, #14, #15, #19) — once these are wrong, the wrong data is in the DB and tests retrofitted later inherit corrupted fixtures (exactly the budgetary-quote scenario).
3. **n8n Code-node smoke test** (#52) — cheapest unblock of the recurring May-21-class debacle. Single test file covers all 20 workflows.
4. **Smoke tests for new pages** (#40-#51) — drop-in additions to `smoke.spec.ts`, each is ~10 LOC.
5. **RPC SQL tests** (#5, #15, #24, #25, #38) — once one harness exists (vitest + Supabase service-role client against dev), the marginal cost per RPC is tiny.

## Process gap (not a test, but related)

The `pnpm build` gate was added 2026-05-24 because `pnpm check-types` misses client/server boundary violations. Same shape of gap exists today around **test fixtures**: lint + types + build all pass with mocks that don't match production data. A linter (or convention) requiring AI/extractor tests to declare their fixture source ("captured from real Claude run on YYYY-MM-DD") would help future agents avoid the ₹0 trap.
